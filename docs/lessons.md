# 工程经验与教训

本文记录这套流水线在真实媒体库上长期运行沉淀下来的认知、设计与踩坑。按「认知 → 设计 → 运维 → 实录」组织，供同类工具的使用者与维护者参考。

---

## 1. 本质认知：加密容器不是音频编码

- `.ncm` / `.mflac` / `.mgg` 等是**加密容器**而非音频编码格式。所谓"解锁"是**字节级无损解密**，解出来的是原始音频流（flac/mp3/…），由解锁器做格式嗅探确定扩展名。**"转码"是伪需求**——任何先转码再处理的方案都在破坏音质且方向错误。
- 解锁工具（本项目的外部依赖 unlock-music CLI）负责两件事：解密 + 格式嗅探。编排层负责其余一切：状态、幂等、保护、去重、台账。
- **新版音乐客户端会把解密密钥移出文件**（放进带密码的本地密钥库 vault）。因此任何工具都只能承诺覆盖「密钥内嵌在文件里」的那部分文件；密钥外置的文件属于另一类问题，不是编排层能解决的。本项目把密钥库通道（`--qmc-mmkv`）留作可选透传参数，但**不承诺**它对新版客户端文件有效。

## 2. 幂等设计五件套

1. **磁盘事实优先，状态文件辅助**：跳过判定先看输出文件是否真的存在（常规文件、非空、ffprobe 可读），再查状态台账。磁盘是唯一事实，台账只是缓存。
2. **机器可判的终态检查**：`--check-idempotent` 遍历全部加密源逐个分类，全部处理完（含永久失败跳过）→ `pending=0` 且退出码 0；否则 `pending=N` 且退出码 1。自动化（cron、CI）靠退出码判断，不解析人话。
3. **防重入主锁**：cron 触发与人工运行撞车是常态，主锁（flock，无 flock 平台用 mkdir 原子性兜底）保证同时只有一个 run。
4. **失败分层**：`no-key/corrupt/conflict` 立即永久失败（重试无意义）；`permission/io/timeout/other` 自动重试，累计 3 次转永久（有界例外）。永久失败需要 `--refresh-failed` 显式重置——"重试"必须是人主动的决定。
5. **删除只作用于副本**：自动删除永远只碰转换产物（`_unlocked/`），且每删一份都记删除日志。原件树在脚本视角里是只读的。

## 3. 原件保护三件套

原件神圣不可侵犯，三条互相独立的防线：

1. **manifest 基线自检**：首次运行登记全部加密源的 `rel + size + mtime`；此后每次运行末尾比对，任何已登记源发生变化 → 告警并退出码 3。新增加密源属正常增量，并入基线不告警。同时编排层**绝不**向解锁器传 `--remove-source`，绝不移动/覆盖/改名原件。
2. **写穿防护（最阴险的一类事故）**：解锁器的纯解密输出路径用 `O_TRUNC` 打开——**会跟随 symlink 并截断目标**。如果输出落点恰好是一个指向原件的 symlink（比如符号链接农场建错了），就会不可逆地截断原库文件。防护：worker 在调用解锁器**之前**，对候选输出全集做 lstat，凡是 symlink → 记 conflict 日志、标永久失败，解锁器根本不启动；symlink 农场则构造性地不给"与加密源同 stem 的通用文件"建镜像；从磁盘事实回写状态前必须 lstat 确认是常规文件。
3. **输出布局镜像化**：产物固定落在 `<music-root>/_unlocked/<源相对父目录>/`，与原件树物理隔离，从根上减少"写回去"的机会。

## 4. 输出布局：镜像树 + symlink 农场

- 产物保持原相对目录结构（歌手/专辑层级），方便播放器按库扫描。
- `--sync-symlinks` 在 `_unlocked/` 里为**非加密**的通用音频与歌词（.lrc）建相对 symlink，让播放器能从单一根看到"完整"库。链接目标按目录深度算 `../` 跳数——**深度差一级就会自指**，务必用公式算而不是手数。
- 与同目录加密源同 stem 的通用音频不建镜像（转换产物会占据同名位置，构造性规避遮蔽）；歌词 `.lrc` 永不与音频产物同名，一律镜像。
- 定期清扫悬空链接；`--unlink-symlinks` 只删链接、绝不碰常规文件。

## 5. 去重的两层策略

- **精确重复**（解密后内容哈希一致）：可以自动删，但流水必须安全——state 反查确认"这份产物是登记在案的输出" → 删除日志先行并 fsync → `mv` 进同文件系统的回收目录（原子 rename）→ 复核保留份哈希仍一致 → 才真正 `rm` → 最后回写状态。任何一步不过就跳过该副本。回收量只以删除日志合计为准（文件系统快照 pin 会让 df 回收滞后数天，属预期）。实测精确去重的收益**远超按文件名口径的预估**——跨平台/跨目录的同曲重复，文件名根本看不出来。
- **近似重复**（跨平台疑似同曲）：**只出报告，零删除**。音质可能不同、版本可能不同（live/重制），必须人工裁决。保留建议序：无损>有损 → 位深×采样率 → 码率 → 标签完整度 → 路径字节序。

## 6. 运维模式

- **cron 追加式安装**：安装定时任务时绝不"重建 crontab"。正确姿势：备份当前 crontab → 逐行检查已存在则跳过 → 追加缺失行 → 校验"追加前已有的每一行都还在 + 目标行都在位"。任何清空重写 crontab 的工具脚本都该被扔掉。
- **防重入主锁**（见 §2）+ **run.pid** 记录持有者，崩溃后可判断陈旧锁。
- **日志超限轮转**：cron 日志超 20MB 时滚动保留 `.1/.2/.3` 三代，防止长年运行把小盘写满。
- **磁盘余量闸**：可用空间低于阈值时清空任务列表，只做 sync/check/自检——绝不把库写满。

## 7. 大文件搬运

- 跨机迁移大音乐库走 **tar 管道流**（`tar -C src -cf - . | ssh dst 'tar -C dst -xf -'`），不落中转盘。
- 长时间大流量 ssh 会**随机截断**（不是开头失败，是中间断）。对策：分批 tar（每批若干 GB）+ 逐文件补传 + **双端字节数对账**（文件数与总字节两侧核对，允许清单噪音行）。永不假设"传完了就是传对了"。
- 远端 GUI 场景（Windows）的坑见 §10 附录。

## 8. 我们踩过的坑（实录）

以下是真实发生过、修掉、并且值得写下来的缺陷。每一条都曾是生产事故或险情：

1. **symlink 农场深度差一级 → 自指链接**：链接建在 `_unlocked/<a>/<b>/` 下，回跳级数少算一级，链接指到自己。批量 `ln -s` 前必须用公式推导跳数，并抽查 `readlink` 结果。
2. **扩展名大小写漏枚举**：`find -name '*.mp3'` 漏掉 `.MP3`。凡按扩展名筛选用大小写不敏感匹配（`-iname` / python 里 lower()），即使你"确认"库里全是小写——确认会过期。
3. **精确字符串匹配被控制字符后缀破坏**：用精确等值匹配去对台账行，而某些行尾带了不可见控制字符（如 `\x1f` 分隔符残留），匹配永远失败。写匹配逻辑时先想清楚"这一行的完整字节长什么样"，或干脆用结构化解析（JSON 字段比较）代替子串匹配。
4. **无斜杠字符串的组件数循环死循环**：计算相对路径深度时，对不含 `/` 的字符串做 `${rest#*/}` 循环——没有 `/` 时替换不生效，循环变量永不变，CPU 100%。循环前先处理"无分隔符"这一分支。
5. **崩溃恢复误伤**：恢复逻辑用子串 grep 找 `in_progress` 的源，把历史上任意一条 in_progress 行都算数，误重置了早已 done 的源。恢复必须只看**每个源最后一行**的状态（"最后写下的才算数"）。
6. **解锁器成功日志在 stdout**：zap ConsoleEncoder 写 os.Stdout，只抓 stderr 会让"全部成功"看起来像"全部失败"。子进程输出永远合并捕获再解析。
7. **解锁器输出目录必须逐源显式传 `-o`**：单文件输入且不指定输出目录时，它会写回源目录——直接破坏镜像布局。绝不依赖工具的"默认行为"。
8. **`--overwrite` 必须恒加**：不传时输出已存在只警告并跳过（退出码还是 0），半截产物会永远留在原地冒充成功。恒加 `--overwrite` 让半截输出在下次运行自愈。
9. **SMB 凭据与网页登录密码不是一回事**：用网页密码挂 SMB 共享报 `net use` 1326（登录失败）。两套凭据体系，别混。
10. **记账口径不一致**：done 行的 `size` 记源文件大小，deduped 行记的是输出大小——不影响幂等判定，但读台账的人会困惑。字段语义要么统一要么写文档。
11. **对第三方工具的错误信息做分类时**，匹配串要覆盖其日志的真实形态（含大小写变体），并把"未匹配的都归 other 自动重试"作为兜底——错误分类错误的代价是把永久失败当临时失败无限重试，或反之。

## 9. 合规与开源化的边界

- 2022 年起，多个网盘/版权方对"规避技术保护措施"类工具发起过批量下架（连带全部 fork）。周边工具在公开平台生存的前提由此明确：**仓库内零规避组件**（算法/密钥/测试向量一个字节都没有）、纯编排、声明克制、外链只给官方自建站、绝不捆绑解锁器二进制。
- 泄露扫描要做成**门禁**而不是自觉：一组固定的私有信息模式（私网地址、机器路径、真实用户名、内部代号、密钥材料指纹、示例内容），发布前全仓 grep 零命中才放行。本项目把这门禁做成了 `scripts/leak-scan.sh` 并挂在 CI 上——连门禁脚本自身都要对这些模式零命中（模式用十六进制转义构造）。
- 编排层与外部工具是「独立程序 + 子进程 + 文件系统/stdout 文本交互」，无源码复制、无进程内链接，许可证上互不传染（上游 MIT 时连争论面都不存在）。README 里把归属与责任划分写清楚。

## 10. 附录：边缘场景（Windows GUI 自动化，供有同类需求者）

- 通过 ssh 直启的 GUI 进程落在**非交互会话**里，桌面上不可见。要进桌面会话用计划任务：`schtasks /create ... /IT` 触发。
- UIA/UI Automation 自动化：先读控件名、**只按白名单点击**；看不懂的弹窗停下来等人工，绝不盲点——自动化脚本的每一次"猜"都是一次真实的系统操作。
- 安装器没有静默参数时，"远程 GUI 安装 + 双重签名校验 + 注册表终验"比破解静默参数更可靠、也更合规。
